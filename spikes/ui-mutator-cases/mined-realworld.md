## Operators the repo's UI does not show

- `StateAttribute`: no `aria-expanded`, `aria-pressed`, `aria-checked` or `aria-selected` anywhere in the
  templates [checked: searched all `.html` at the pin].
- `LabelAttribute` with `aria-label`, `alt` as a plain string, `title`, `htmlFor`: none; the only plain-string
  label attribute is `placeholder` (cases 2). The e2e suite uses `placeholder`, never `getByLabel`/`getByRole`.
- `ElementRole` `RoleRemoval`: no `role` attribute.
- `ListExpression` is a later operator; the `@for` loops would feed it.

## No JSX equivalent

- `libs/articles/feature-articles-list/src/article-list.component.html:11` `@for (...) { ... } @empty { <div>No articles are here... yet.</div> }`: `@empty` has no JSX form (a `.map` plus a length ternary changes the shape).
- `libs/home/feature-home/src/home.component.html:45` `@defer (when !!$tags().length) { ... }`: no JSX form.
- `[ngClass]="{ active: ... }"`, `routerLinkActive="active"`, `[routerLinkActiveOptions]` (navbar, pager, home): framework directives, no JSX form, no operator targets them.
- `libs/articles/feature-article/src/article-meta/article-meta.component.html:32` `{{ ... ? 'Unfollow' : 'Follow' }}` inside text: an interpolation that holds a ternary of strings. In JSX it is a `ChildExpression` whose value is a conditional of two string literals, which the built-in `StringLiteral` already mutates, so its `ChildExpressionRemoval` is the only UI mutant. Left out because the Angular form mixes text and interpolation in one text node.
- `libs/home/feature-home/src/home.component.html:13` `@if ({ listConfig: $listConfig() }; as model)`: an `@if` used only to alias a value; no JSX form.
- `<cdt-icon [name]="Icon.Heart" />` and other component bindings: custom component props; no operator targets them.
